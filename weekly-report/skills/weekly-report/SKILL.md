# 週報作成スキル

所定のフォーマットに従い、ビジネス向けに簡潔な文体で週報を作成するためのスキルです。

## 週報ファイルの保存先

週報の読み書きは、常に下記の固定パスに対して行います。
`<週報ディレクトリ>/週報.html`

導入時に実際のパスへ置き換えてください。
このスキルはどのフォルダから呼び出されても、上記の固定パスを基準に動作します。
「作業ディレクトリ」ではなく、必ずこの固定パスを使ってください。

## 利用者の役割（文脈情報）

導入時に利用者の所属・役割を記載してください。
例として、所属部門、担当業務（開発／PM など）、チームリーダとしての立場などを記載します。
この情報は、週報の粒度や観点（マネジメント視点か実務視点か）を決めるために使われます。

## 対象期間の決め方

週報を書くタイミングのその週を対象とします。
作業内容は今週（月曜〜金曜）を対象とします。
今後の作業予定は翌週（月曜〜金曜）を対象とします。
例として、週報を記載するタイミングが5/1（金）であれば、作業内容は4/27（月）〜5/1（金）、今後の作業予定は5/4（月）〜5/8（金）が対象になります。
今日の日付を基準に、まず対象期間を確定してからレポートを書き始めてください。

## 作成手順

1. 今日の日付から、作業内容の対象期間（今週の月〜金）と今後の作業予定の対象期間（翌週の月〜金）を確定する。
2. 前回作成した週報がある場合は、それをベースに差分を反映する（後述「前回週報からの差分反映」を参照）。前回週報がない場合は新規に作成する。
3. 作業内容は、チャットで入力された内容をベースに案件・作業ごとに簡潔にまとめる。
4. 今後の作業予定は、チャットで伝えられた内容に加えて、翌週に開催される会議、議事録、スケジュールなども参考にして案件・作業ごとにまとめる。
5. 各項目を下記フォーマットに当てはめて出力する。
6. 必須項目（トピックス・作業内容・今後の作業予定・課題）は必ず埋める。
7. 任意項目（連絡事項・コメント）は該当する内容があれば記載し、なければ省略するか「特になし」とする。
8. 週報のテキストを確定したら、ボタン押下でコピーできるHTMLファイルを作成する（後述）。

## 前回週報からの差分反映

前回作成した週報をベースとし、チャットで伝えられた変更点（差分）のみを取り込んで今回の週報を作成します。
毎回ゼロから入力し直す必要をなくし、変わった部分だけを伝えれば週報が更新される運用とします。

手順です。
固定パスの週報.htmlから前回の週報本文を読み取り、これを今回のベースとします。
週報.htmlが存在しない場合は前回週報なしとみなし、新規に作成します。
チャットで伝えられた変更点（例として「A案件は完了したので削除」「B案件に〇〇のレビュー対応を追加」「トピックスを△△に変更」など）を、前回週報の該当箇所に反映します。
変更点として言及されていない案件・項目は、前回週報の記載を維持します。
対象期間（今週・翌週）は今日の日付を基準に再計算し、必ず今回の期間に更新します。
前回の「今後の作業予定」に記載した内容のうち、今週実施したものは「作業内容」へ移すことを検討します。
差分反映後は、変更前後で何を変えたのかを簡潔にチャットで報告してから、確定した本文でHTMLを作成します。

## 文体・記述ルール

文体はビジネス向けに簡潔にしてください。
太字は使わないでください。
句点の度に改行をしてください。

## レイアウトルール

案件・作業ごとに「■ 案件名」の小見出しを設け、その配下を「・」の箇条書きでまとめます。
各案件（■）の間には空行を1行入れます。
すみカッコの小見出し（【トピックス】など）の前後にも空行を入れます。
箇条書きの各行は句点で終えず、簡潔な体言止め・名詞句でそろえます。
複数案件をまとめる場合は、行末に対象案件名を（〇〇案件）のように添えます。

## 出力フォーマット

```
【トピックス】

・今週一週間のポイントを一言で

【作業内容】

■ 案件A
・作業内容を箇条書きで
・作業内容を箇条書きで

■ 案件B
・作業内容を箇条書きで

【今後の作業予定】

■ 案件A
・作業予定を箇条書きで

■ 案件B
・作業予定を箇条書きで

【課題】

・案件・作業を進める上で感じた課題

【連絡事項】

・休暇の予定など前もってわかっていること

【コメント】

・案件・作業に関連していなくても伝えたいこと
```

## 各項目の説明

トピックス（必須）。
今週一週間をひと言でいうと何がポイントだったのか、とそれに関連したコメント等を記載します。

作業内容（必須）。
案件・作業ごとに簡潔に記載します。
チャットで入力された対象案件の内容をベースにします。

今後の作業予定（必須）。
案件・作業ごとに簡潔に記載します。
チャットで伝えられた内容に加え、翌週の会議や議事録、スケジュールも参考にします。

課題（必須）。
案件・作業を進める上で感じた課題を記載します。

連絡事項（任意）。
休暇の予定など前もってわかっていることを予め記載します。

コメント（任意）。
案件・作業に関連していなくても、何か伝えたいことがあれば記載します。

## コピー用HTMLファイルの作成

週報のテキストが確定したら、固定パスの週報.htmlにHTMLを作成します。
このHTMLは、画面に週報を表示し、右上の「コピー」ボタン押下で全文をクリップボードにコピーできるものです。

要件です。
週報の本文を画面に表示します。
「コピー」ボタンを設置し、押下で navigator.clipboard.writeText によりクリップボードへコピーします。
navigator.clipboard が使えない環境向けに、範囲選択して document.execCommand('copy') する代替処理も用意します。
コピー後はボタン表示を「コピー完了」に変え、画面下にトーストで「コピーしました」と通知し、2秒後に元へ戻します。
ファイル作成後は open コマンドでブラウザを開いて確認します。

HTMLの生成は `scripts/build_report.py` を利用することもできます。
本文テキストを渡すと、テンプレートに差し込んでHTMLを出力します。
